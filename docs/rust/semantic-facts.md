# Semantic facts and deterministic test support

Status: Active implementation contract

`hq-domain::SemanticFact` is the only input fact shape for causal reduction. It contains a
content-derived opaque identity, verified installation author, explicit authored time, signed
semantic scope, bounded causal parents with typed authority roles, and one exhaustive
`SemanticPayload`. Cryptographic signatures, hashes, canonical bytes, relay wrappers, storage
receipts, and arrival metadata remain outside this type.

## Catalog coverage

`FactKind::ALL` maps every family from `FCT-001` through `FCT-048` to its exact stable name,
protocol class, and retention class. `SemanticPayload` has one correspondingly named variant per
family. The test suite performs three complementary checks:

- it compares the code catalog to all 48 expected IDs and names in stable order;
- it extracts the table rows from `semantic-fact-catalog.md` and requires exact bidirectional
  equality; and
- `hq-testkit` constructs every payload variant and requires their reported kinds to equal
  `FactKind::ALL`.

Payload fields use only validated domain primitives and typed records. Reused records represent
genuinely common semantics: repository context, message content/presentation, operation
correlation, project resources, assignment bindings, runtime observations, and remote outcomes.
The normative validation, authority, conflict, projection, and observation rules remain in the
semantic catalog; reducers implement the non-intrinsic causal rules.

Harness activity additionally carries typed optional item correlation, activity kind/status,
runtime-lifetime identity, positive source sequence, signed occurrence time, and explicit
truncation. Completed activity also carries a required closed presentation when its kind is
`CompletedItem`: separately bounded command/output/exit, file path/diff, tool name, web query, or
explicit unknown. Non-completed activity must not carry that field. These signed values drive
reducer-owned coalescing and presentation; flattened activity content remains inert technical text.
Project-attributed activity also carries a typed project, dispatch, captured assignment binding,
and immutable thread. This is an in-place pre-release FCT-022 schema change without a compatibility
branch. The normalized rules are documented in `docs/rust/conversation-model.md`.

`SemanticFact::new` enforces the intrinsic envelope boundary. Remote-control payloads require a
`RemoteControl` scope and canonical payloads reject it. Installation declarations must match their
verified author and installation-private scope. Message-root and project-output purposes cannot be
mislabelled, project output must name its enclosing project, a project's primary resource must be
present in its desired resource set, and a remote request's target home must match its scope.

Remote request, receipt, and outcome variants are signed semantic records but remain in the
`RemoteControl` protocol class. They cannot be passed off as canonical project facts and therefore
cannot mutate project state directly.

## Deterministic testkit

`hq-testkit` contains no ambient clock or random source:

- `DeterministicValues` uses an explicit seed and reproducible byte stream to generate every opaque
  ID, public key, and command digest type. `fork` clones an exact stream position.
- `DeterministicClock` advances from explicit signed millisecond start and step values.
- `FactBuilder` creates valid root/child facts with explicit parent and authority edges and exposes
  stable fixtures for every payload family.
- `arrival_permutations` exhausts schedules for deliberately small input sets. It is not intended
  for unbounded production-sized collections.
- `StateMachineSequence` retains explicit ordered inputs and produces prefix or remove-one shrink
  candidates without hidden entropy.

Generated bytes are test data, never production identity material or cryptographic entropy.
Generated graphs prove construction and scheduling behavior but are not assumed semantically usable
until the reducer validates their dependencies, authorities, and domain conflicts.
